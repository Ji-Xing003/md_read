# 标签页拖拽排序设计

日期: 2026-08-18
状态: 已批准

## 目标

标签栏标签可拖拽重排顺序, 松手落位; 新顺序写回会话持久化, 重启保持。

## 不做的事

- 不做右键菜单 / 键盘移动 (仅拖拽)。
- 不做拖拽时切活动标签 (活动标签保持不变)。
- 不做多标签同拖 / 跨窗口拖。
- 不做撤销。

## 交互

- HTML5 drag & drop: 标签元素 `draggable=true`。
  - `dragstart`: 记录被拖标签索引。
  - `dragover`: 计算插入点 (悬停标签左半/右半), 显示插入指示条 (竖线, 明暗主题各配色), `preventDefault` 允许 drop。
  - `drop`: 把被拖标签移动到插入点 (DOM 重排), 清除指示条, 发一次 IPC。
  - `dragend`: 清除指示条 (含取消情况)。
- 只动 DOM 顺序 + 一次 IPC — 不重建页面, 无闪烁。
- 单标签时拖拽无操作 (拖放同一位置也 no-op)。
- 活动标签不变: DOM 移动不改变活动状态类, 渲染内容不动。

## IPC 与持久化

- IPC 格式: `tab-move:<from>:<to>` (两非负整数, 冒号分隔)。语义: `from`/`to` 是**索引** (Vec 顺序 = DOM 顺序, 前端按 DOM 索引发送); Rust 按 `remove(from)` + `insert(to)` 执行, 与前端 DOM 移动的最终序一致。
- Rust: 解析两个 `usize`, 越界或相等 → 忽略 (不发错不崩溃); 否则 `session.tabs` 移除 `from` 插入 `to`, 然后调用现有会话保存函数 (会话文件已存标签顺序, 无需新文件)。移动后不重建标签 DOM (前端已重排, 避免闪烁)。
- 重启后按新顺序恢复 (现有会话恢复逻辑不动)。

## 错误处理

- IPC 负载非法 (非数字、越界、from==to) → 忽略, 不写会话。
- 拖拽被浏览器取消 (dragend 无 drop) → 仅清指示条, 不发 IPC, DOM 无变化。

## 测试

- Rust 单测: `tab-move` 处理函数 — 合法移动改变 Vec 顺序且触发保存; from==to / 越界 / 非数字被忽略。
- 模板断言: 标签含 `draggable="true"`、拖拽 JS 存在 (dragstart/dragover/drop 处理)、`tab-move:` IPC 字符串存在、指示条元素存在。
- 会话往返: 保存含重排后顺序的会话, 恢复后顺序一致 (若现有会话测试可扩展则扩展, 否则新测试)。
- 现有 38 个测试保持通过。
- 手动: 开多个课程 md, 拖标签换序, 重启验证新序; 拖到边缘/取消验证无残留。
